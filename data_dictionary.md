# Data Dictionary

## `data/mapping_register.csv`

| Field | Description |
| --- | --- |
| `mapping_id` | Unique field-level STTM mapping identifier. |
| `business_domain` | Conversion domain such as Customer Master, Payments, or Asset Register. |
| `source_system` | Synthetic legacy source system. |
| `source_table` | Synthetic source table feeding the conversion. |
| `source_field` | Source field in the STTM row. |
| `target_object` | Destination table or object. |
| `target_field` | Destination field. |
| `data_type` | Simplified target data type. |
| `criticality` | Business criticality used in readiness scoring. |
| `mapping_complexity` | Direct, lookup, derived, reference decode, or currency conversion. |
| `transformation_rule` | Business-readable mapping logic for development and sign-off. |
| `lineage_path` | Synthetic data flow from source to staging, load-ready, and target layers. |
| `signoff_status` | Current approval state for the STTM row. |
| `owner_group` | Business or operations owner for decisions and remediation. |
| `google_sheet_tab` | Workbook-style tab where the mapping would be reviewed. |

## `data/reconciliation_results.csv`

| Field | Description |
| --- | --- |
| `batch_id` | Conversion verification batch. |
| `mapping_id` | Mapping row being reconciled. |
| `load_ready_rows` | Record count in the load-ready file or table. |
| `target_rows` | Record count in the destination table. |
| `row_count_delta` | Target rows minus load-ready rows. |
| `matched_keys_pct` | Percent of business keys matched between load-ready and destination. |
| `value_match_pct` | Percent of compared values that match after transformation. |
| `null_delta_pct` | Target null-rate drift against the approved mapping expectation. |
| `duplicate_keys` | Duplicate transformed business keys detected. |
| `orphan_records` | Records missing required reference lookups. |
| `amount_variance_usd` | Numeric variance for amount-like fields. |
| `reconciliation_score` | Transparent score from parity, key match, value match, null drift, and exception counts. |
| `recon_status` | Pass, Watch, Mapping review, or Fail. |
| `blocker_reason` | Plain-English blocker or monitoring reason. |
| `audit_query_id` | Synthetic SQL audit identifier. |

## `data/data_quality_findings.csv`

| Field | Description |
| --- | --- |
| `finding_id` | Unique audit finding id. |
| `mapping_id` | Impacted mapping. |
| `severity` | High, Medium, or Low. |
| `issue_type` | Row count variance, null drift, duplicate key, reference miss, value variance, or mapping ambiguity. |
| `sql_check` | Named SQL check that raised the finding. |
| `observed_signal` | What the audit detected. |
| `root_cause` | Likely technical or business root cause. |
| `business_impact` | Stakeholder-facing implication. |
| `owner_group` | Group responsible for follow-up. |
| `status` | Open, In review, or Ready for retest. |
| `aging_days` | Days since the finding was opened. |

## `data/incident_triage.csv`

| Field | Description |
| --- | --- |
| `incident_id` | Verification incident id. |
| `mapping_id` | Impacted mapping. |
| `verification_phase` | SIT exit, UAT cycle, mock cutover, or sign-off review. |
| `severity` | High or Medium. |
| `root_cause_category` | Broad category used for status reporting. |
| `status` | Incident state. |
| `opened_date` | Synthetic opened date. |
| `aging_days` | Days since opening. |
| `business_impact` | Why stakeholders should care. |
| `next_update` | Next communication or action. |
| `resolution_path` | Expected remediation and retest path. |

## Generated Outputs

`analysis/outputs/priority_queue.csv`, `signoff_queue.csv`, `reconciliation_summary.csv`, `incident_status.csv`, `summary.json`, and `app_payload.json` are generated by the scoring script. These files power the UI and keep the case study reproducible.
